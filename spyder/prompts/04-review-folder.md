# Prompt 04 — One place for every image (the review folder)

You are working on the Spyder web game in `E:\Projects\retro-ports\spyder`. **Runs alone, before 05 and 06.**

## Why

Screenshots are scattered over 40+ folders (`game/screens/`, `game/rooms/*/screens/`, `game/tools/out/**`, about 900 MB). The owner cannot find what to review. From now on there is one review place, one scratch place, and a gallery page. The rule is already written in `ART-DIRECTION.md` §15, "Where images go" — read it first; this prompt implements it and migrates what exists.

## Read first

1. `ART-DIRECTION.md` §15 (the new "Where images go" section is binding).
2. `game/tools/*.mjs` (`common.mjs`, `shoot.mjs`, `regress.mjs`, `flowtest.mjs`, `checks.mjs`, `perf.mjs`, `tabs.mjs`), `game/rooms/front-porch/playtest.mjs`, `game/rooms/front-porch/perf.mjs`, `game/rooms/kitchen/playtest.mjs`.
3. `game/NOTES.md` sections "QA hooks" and "Hero frames".

## Rules

- No change to game behaviour or visuals. Only tools, paths, docs, and file moves.
- No new npm dependencies beyond `playwright-core` (already installed). Compose JPEG sheets in a headless page with a `<canvas>` and `toDataURL('image/jpeg', q)`; take screenshots with `type: 'jpeg'`.
- Humanized code. No git commits.

## 1. Build `game/tools/review.mjs`

An ES module that every tool imports, plus a small CLI.

| Export / command | Does |
|---|---|
| `paths` | Absolute paths: `spyderRoot`, `reviewRoot` (`<spyder>/review`), `scratchRoot` (`<spyder>/.scratch`). |
| `scratchDir(name)` | Creates and returns `.scratch/<name>/`. Every tool's default output goes here. |
| `saveHero(page, target, state)` | Screenshots the page as JPEG quality 90, 1920 × 1080, to `review/current/<target>/<state>.jpg`. `target` is a room id (`front-porch`, `living-room`, `kitchen`, …) or `shell` for title/map/settings/howto. |
| `makeSheet(promptId, cells)` | `cells = [{ src, label }]`. Builds `review/prompts/<promptId>/sheet.jpg`: 1920 px wide, 2 columns of 960 × 540 cells, quality 80, each cell with a small caption strip (label in the game's Special Elite font, `linen` on `soot`). |
| `writeSummary(promptId, markdown)` | Writes `review/prompts/<promptId>/summary.md`. |
| `node review.mjs gallery` | Rebuilds `review/index.html` (see 2). |
| `node review.mjs audit` | Lists every `.png/.jpg/.jpeg/.webp/.gif` under `spyder/` that is **not** in `review/`, `.scratch/`, `reference/screens/`, `reference/fonts/`, `original/`, `spec/`, `src/`, `_archive/`, or any `node_modules/`. Prints nothing and exits 0 when clean; otherwise prints the paths and exits 1. |

## 2. The gallery: `review/index.html`

A static page generated by `node review.mjs gallery` (data embedded in the page, because `file://` cannot fetch JSON). Opens from disk with no network. Plain HTML, CSS and a little JS.

- **Header:** "Spyder — review", the date it was generated, and a short legend.
- **Prompts, newest first:** one card per `review/prompts/<id>/` with the prompt id, date, its `sheet.jpg` (click to enlarge), and its `summary.md` rendered as simple HTML (headings, lists, tables, bold, code — a tiny Markdown subset is enough).
- **Current frames:** one row per target in house order (`shell`, then rooms by number: front-porch, living-room, family-room, kitchen, dining-room, …), thumbnails of every state in a fixed order (`title, map, settings, howto` for shell; `dirty, action, makeover, clean, results`, then extras like `tutorial`, `jumper`, for rooms). Click to enlarge; arrow keys move between frames of the same row; Esc closes.
- **Reference:** the six frames from `../reference/screens/` in the same thumbnail style, labelled "Quality bar".
- Look: quiet and neutral so the frames stand out: background `#16120F`, text `#E8DCC6`, headings in the bundled Fraunces (`../game/fonts/`), thumbnails with a 1 px `#3E3128` border, generous spacing. Works in light of the room's dark frames; no light theme needed.

## 3. Repoint every tool

- Every default output path (`tools/out/...`, `game/screens`, `rooms/*/screens`) becomes a `scratchDir(...)`, except hero frames, which go through `saveHero`.
- `shoot.mjs --hero` saves the shell's frames and every registered room's standard states through `saveHero`. Add `--room=<id>` to limit it to one room.
- Room QA scripts (`rooms/front-porch/playtest.mjs`, `rooms/front-porch/perf.mjs`, `rooms/kitchen/playtest.mjs`) move into `game/tools/rooms/` and write only to scratch.
- `regress.mjs`, `flowtest.mjs`, `checks.mjs`, `perf.mjs` write their screenshots to scratch.

## 4. Migrate what exists

1. Run `node shoot.mjs --hero` so `review/current/` gets fresh frames for `shell` (`title, map, settings, howto`) and for `front-porch`, `living-room`, `kitchen` (`dirty, action, makeover, clean, results`, plus `tutorial` for the porch and `jumper` for the kitchen). Fresh renders are better than converting old PNGs, which may predate prompt 03.
2. Move the existing review sheets:
   - `game/tools/out/review/03-polish.jpg` → `review/prompts/03-polish/sheet.jpg`
   - `game/tools/out/review/03-polish-fix-1.jpg` → `review/prompts/03-polish-fix-1/sheet.jpg`
   - the architect's sheets `game/tools/out/review/{shell,porch,kitchen,makeovers,regression}.jpg` → `review/prompts/00-02-architect-review/` (keep their names; the gallery shows the first as the card image and the others below it).
3. Write `summary.md` for `00-02-architect-review`, `03-polish` and `03-polish-fix-1` from `game/NOTES.md` (5–10 lines each: what changed, check counts, verdict "approved").
4. **Delete** after the counts check out: `game/tools/out/` (everything, including `make-sheets.ps1`), `game/screens/`, `game/rooms/front-porch/screens/`, `game/rooms/kitchen/screens/`. These are regenerable QA output; the curated frames now live in `review/`.
5. `.gitignore` in `E:\Projects\retro-ports\` — add `spyder/.scratch/` next to the existing Spyder exception.

## 5. Docs

- `game/NOTES.md`: replace the "Hero frames" section and any `tools/out` / `screens/` paths with the review folder; add a short "Images" section pointing to `ART-DIRECTION.md` §15.
- Room `NOTES.md` files: fix paths that pointed to the deleted folders.
- `prompts/README.md` is maintained by the architect — leave it.

## Done when

- `node review.mjs audit` prints nothing.
- `node review.mjs gallery` produces a page that shows all prompts, all current frames and the reference row; open it in the headless browser and check there are no broken images.
- `checks.mjs` and `flowtest.mjs` still pass (counts in the summary).
- `.scratch/` is emptied at the end.

## Deliverable — then STOP

- `review/prompts/04-review-folder/sheet.jpg`: two cells — a screenshot of the top of `review/index.html` (prompt cards) and one of the "Current frames" section.
- `review/prompts/04-review-folder/summary.md`: what moved, what was deleted (folder list and total MB freed), audit result, check counts.
- Rebuild the gallery once more so it includes prompt 04.

Then stop.
