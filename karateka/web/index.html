Karateka

A browser port of the 1986 Brøderbund IBM PC game. Every pixel is decoded at runtime from your own copy of the game's data files — nothing is baked into the code. Two modes: game plays the fight, viewer steps through the source animation libraries frame by frame.

G game   V viewer   R restart   P pause
game mode: ←→ walk (hold Shift to run) ASD punch hi / mid / lo ZXC kick hi / mid / lo
viewer mode: ←→ previous / next move ↓↑ actor left / right [] scroll camera left / right ,. step frame back / forward Space pause / play L next library B toggle backdrop T self-test

Where to put the game files. Copy your KARATEKA.EXE and its 90 data files (BCG, DAT, IND, ALL*, BAL*, CAL*) into ../original/ (which .gitignore blocks), then serve karateka/ with python -m http.server.

What this viewer shows. Each fighter's move library is 47–51 short animations. Pick a library, pick a move, and this steps through its frames at the game's animation rate. Every frame is composed the same way the port will compose them: backdrop into shadow buffer, then each fig's KS sprite combined with its KM alpha mask, written to the buffer at the frame's own coordinates.

What is not here yet. Combat — input, hits, damage, opponent AI. Scene composition from BAL/CAL scripts (that gives the level backdrops, gate, wall, ground plateau). Level progression. The order these come in and the honest scope is in ../docs/06-web-code.md.

Written from a byte-identical reconstruction of KARATEKA.EXE. The reconstruction, the decoder tests and this viewer's code live in this repository. The game data does not. Original game © 1986 Brøderbund Software.
